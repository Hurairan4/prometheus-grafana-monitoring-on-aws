# Configuration Guide

## Overview

This document explains the configuration of each component in the monitoring stack deployed on the AWS EC2 instance.

The monitoring solution consists of:

- Prometheus
- Node Exporter
- Grafana
- Alertmanager

---

# Prometheus Configuration

Prometheus is responsible for collecting and storing infrastructure metrics.

The primary configuration file is:

```
configs/prometheus.yml
```

The configuration defines:

- Global scrape interval
- Evaluation interval
- Scrape targets
- Alertmanager endpoint
- Alert rule files

The configured scrape targets include:

- Prometheus Server
- Node Exporter

---

# Node Exporter Configuration

Node Exporter requires minimal configuration.

Once installed, it exposes Linux system metrics through an HTTP endpoint.

Prometheus periodically scrapes this endpoint to collect metrics.

The exporter provides metrics for:

- CPU Usage
- Memory Utilization
- Disk Usage
- Filesystem Statistics
- Network Statistics
- System Load
- Running Processes

---

# Grafana Configuration

Grafana was configured to use Prometheus as its primary data source.

Configuration steps included:

- Accessing the Grafana web interface
- Adding Prometheus as a data source
- Verifying successful connectivity
- Importing monitoring dashboards
- Configuring dashboard refresh intervals

Grafana retrieves metrics directly from Prometheus for visualization.

---

# Alert Rules Configuration

Prometheus evaluates alert rules continuously.

The alert rules are stored in:

```
configs/alert_rules.yml
```

The project includes alerts for:

- High CPU Usage
- High Memory Usage
- Instance Down

Each rule specifies:

- Alert name
- Expression
- Threshold
- Duration
- Labels
- Annotations

---

# Alertmanager Configuration

Alertmanager processes alerts generated by Prometheus.

The configuration file is:

```
configs/alertmanager.yml.example
```

The configuration includes:

- Email receiver
- SMTP server
- Authentication
- Notification routing
- Alert grouping

Email notifications are delivered through Gmail SMTP.

---

# Linux Services

Each monitoring component was configured to run as a systemd service.

Configured services include:

- Prometheus
- Grafana
- Alertmanager

Using systemd provides:

- Automatic startup after reboot
- Simplified service management
- Status monitoring
- Restart capability

---

# Network Configuration

AWS Security Groups were configured to allow access to the required services.

| Service | Default Port |
|----------|-------------:|
| Grafana | 3000 |
| Prometheus | 9090 |
| Node Exporter | 9100 |
| Alertmanager | 9093 |

SSH access remained restricted to authorized users.

---

# Configuration Validation

After configuration, the deployment was validated by:

- Verifying Prometheus targets were in the **UP** state.
- Confirming Grafana dashboards displayed live metrics.
- Ensuring Alertmanager received alerts from Prometheus.
- Sending test email notifications.
- Checking all monitoring services were running successfully.

After completing the configuration, all monitoring components communicated successfully and provided a complete infrastructure monitoring solution capable of collecting metrics, visualizing performance, and delivering automated alerts.
